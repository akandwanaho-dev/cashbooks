# Cashbook Native Mobile & Desktop Blueprint

## 0. What “native” means here

This is **not a PWA**. Capacitor packages the existing React application in real Android and iOS projects and produces signed `.aab`/`.apk` and `.ipa` binaries with access to native APIs. Tauri packages the same UI into signed Windows and macOS applications (`.exe`/`.msi`, `.app`/`.dmg`).

Capacitor is a native shell containing a system WebView; it does not turn React DOM components into UIKit/Jetpack Compose controls. A requirement for native UI controls rather than a native binary would require a React Native, Swift and/or Kotlin rewrite. The architecture below preserves the current website and produces store-distributable native binaries.

Capacitor no longer maintains an official Electron target. The old community Electron adapter is not recommended for a new production app. This project uses **Tauri 2** for Windows/macOS because it has a much smaller runtime and a maintained security model.

## 1. Resulting architecture

```text
digital-cashbook/
├── android/                         # generated by `npx cap add android`
├── ios/                             # generated by `npx cap add ios` (build on macOS)
├── src-tauri/                       # checked-in Tauri 2 desktop shell
│   ├── capabilities/default.json
│   ├── src/{lib.rs,main.rs}
│   ├── Cargo.toml
│   └── tauri.conf.json
├── src/
│   ├── contexts/
│   │   ├── AppContext.tsx           # auth, cloud sync, realtime, offline outbox
│   │   └── CurrencyContext.tsx      # UGX-first historical currency engine
│   ├── lib/
│   │   ├── offlineStore.ts          # IndexedDB/Dexie cache + mutation outbox
│   │   └── supabaseClient.ts
│   ├── services/
│   │   └── notificationService.ts   # mobile OS reminders + Tauri notification API
│   └── ...existing React files
├── supabase/
│   ├── schema.sql
│   └── mobile_migration.sql         # currencies, liabilities, preferences, timestamps
├── capacitor.config.ts
├── NATIVE_BUILD_GUIDE.md
└── package.json
```

The online database remains the source of truth. A per-user local cache renders immediately offline. Writes are optimistic and queued in an outbox, then replayed through Supabase and its RLS policies after connectivity returns.

## 4. Generate Android and iOS projects

Run each `cap add` exactly once. Generated projects should then be committed to source control because they contain signing, icons, entitlements and native customizations.

```bash
npm run build
npx cap add android
npx cap add ios       # generate/build iOS on macOS
npx cap sync
```

Normal development cycle after changing React or plugins:

```bash
npm run native:sync  # runs Vite build, then `cap sync`
npx cap open android
npx cap open ios
```

For live device development only:

```bash
npx cap run android
npx cap run ios
```

Do not set Capacitor `server.url` in release configuration. Release builds must load the packaged `dist` assets, not a remote website.

### Android notification resources

Create a white-only transparent status icon named:

```text
android/app/src/main/res/drawable/ic_stat_cashbook.png
```

The filename matches `smallIcon: 'ic_stat_cashbook'` in `capacitor.config.ts`.

For exact due-date reminders on Android 12+, inspect the merged manifest in Android Studio. If the plugin/version does not merge it automatically, add this above `<application>`:

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
```

Do **not** use `USE_EXACT_ALARM` unless the Play policy explicitly permits the app category. The implementation requests user-controlled exact-alarm access and falls back to an inexact alarm when declined. Android 13 notification permission is requested at runtime. Some manufacturer battery savers can still delay alarms, and Android “Force stop” prevents all app alarms until the user opens the app again—an OS rule no plugin can bypass.

### iOS notification configuration

Local notifications need no remote-push certificate. The service requests `UNUserNotificationCenter` permission following a user action. Add the desired app icons in `ios/App/App/Assets.xcassets`, choose the signing Team in Xcode, and verify the bundle identifier.

## 5. Build signed Android binaries

Open Android Studio and configure **Build > Generate Signed Bundle / APK**. The Play Store expects an Android App Bundle (`.aab`), while an `.apk` is useful for direct QA installs.

Command-line release build after signing is configured:

```bash
npm run native:sync
cd android
./gradlew bundleRelease       # Google Play: app/build/outputs/bundle/release/*.aab
./gradlew assembleRelease     # QA APK: app/build/outputs/apk/release/*.apk
```

On Windows, use `gradlew.bat`. Keep the keystore and passwords outside Git; inject them through CI secrets or an untracked `keystore.properties`.

## 6. Build a signed iOS binary

This must run on macOS:

```bash
npm run native:sync
npx cap open ios
```

In Xcode:

1. Select the App target.
2. Set Signing Team and bundle ID.
3. Select “Any iOS Device (arm64)”.
4. Choose **Product > Archive**.
5. In Organizer, validate and distribute to TestFlight/App Store.

A CI/archive flow can use:

```bash
xcodebuild -workspace ios/App/App.xcworkspace \
  -scheme App -configuration Release \
  -archivePath build/Cashbook.xcarchive archive

xcodebuild -exportArchive \
  -archivePath build/Cashbook.xcarchive \
  -exportOptionsPlist ios/ExportOptions.plist \
  -exportPath build/ios
```

The export creates the signed `.ipa`. `ExportOptions.plist` depends on your Team ID and App Store/ad-hoc method, so it must be generated for the owner’s Apple account rather than hard-coded here.

## 7. Build Windows and macOS desktop clients with Tauri

The checked-in `src-tauri` shell uses Tauri 2 and the native notification plugin.

```bash
# Install Rust once:
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup update stable

# Development
npm run desktop:dev

# Production packages for the current OS
npm run desktop:build
```

Typical outputs:

```text
src-tauri/target/release/bundle/nsis/*.exe
src-tauri/target/release/bundle/msi/*.msi
src-tauri/target/release/bundle/macos/*.app
src-tauri/target/release/bundle/dmg/*.dmg
```

Cross-compiling a polished Windows package from macOS (or vice versa) is not recommended; build each target on its own signed CI runner.

- Windows: configure a code-signing certificate in Tauri/CI to avoid SmartScreen warnings.
- macOS: sign with Developer ID, enable hardened runtime, and notarize with Apple.
- Microsoft Store and Mac App Store builds require their respective identity, entitlement and signing configuration.

The Tauri notification API can display native desktop notifications. Unlike Android/iOS, the stock desktop plugin does not register future notifications with an OS alarm manager after the process exits. If desktop reminders must fire while the app is fully exited, add a platform-specific Rust scheduler (Windows Task Scheduler and macOS LaunchAgent/UserNotifications) or run a signed tray/background companion. Do not simulate that promise with JavaScript timers.

## 8. Multi-currency model (UGX default)

`CurrencyContext.tsx` provides:

- UGX default and ISO-aware formatting
- global display-currency preference through Capacitor Preferences
- cached reference rates for offline startup
- conversion using **UGX as the base anchor**
- an immutable historical rate on each transaction

Conversion formula:

```text
historical UGX value = original amount × transaction.exchange_rate_to_ugx
display value        = historical UGX value ÷ current target rate_to_ugx
```

If original and display currencies match, the original amount is returned exactly. Rate changes therefore never rewrite a historical amount.

Creating a transaction:

```ts
const input: TransactionInput = {
  date: '2026-10-05',
  description: 'Export sale',
  type: 'debit',
  amount: 250,
  currency_code: 'USD',
  exchange_rate_to_ugx: 3725.50, // captured now and never silently changed
  category: 'Sales',
}
await addTransaction(input)
```

The bundled rates are explicitly offline fallbacks, not a live financial feed. In production, fetch rates from a trusted Supabase Edge Function or your backend, validate them, then call `updateRates()`. Do not expose a paid FX-provider secret in React code.

Run this upgrade for an existing database:

```text
Supabase Dashboard → SQL Editor → supabase/mobile_migration.sql
Supabase Dashboard → SQL Editor → supabase/product_migration.sql
```

For a new database, run `schema.sql` and then `mobile_migration.sql`. The migration adds:

```text
amount                    numeric(20,4)  # original currency amount
currency_code             ISO 4217 code
exchange_rate_to_ugx      numeric(20,8)  # UGX per one source-currency unit
updated_at                sync/conflict timestamp
```

It also adds RLS-protected `user_preferences` and `liabilities` tables.

## 9. Native reminder API

Daily reminder:

```ts
import { scheduleDailyReminder, cancelDailyReminder } from '@/services/notificationService'

await scheduleDailyReminder('19:30')
await cancelDailyReminder()
```

Loan/debt due reminder:

```ts
import { scheduleDebtReminder, cancelDebtReminder } from '@/services/notificationService'

await scheduleDebtReminder({
  debtId: liability.id,          // stable UUID from Supabase
  name: 'SACCO loan payment',
  amountLabel: 'USh 450,000',
  dueDate: liability.due_date,
  daysBefore: 1,
  time: '09:00',
  recurrence: 'monthly',
})

// Always cancel when paid/deleted:
await cancelDebtReminder(liability.id)
```

The UUID is hashed to a stable Android 32-bit notification ID, so edits replace the existing alarm instead of creating duplicates. Mobile schedules are owned by Alarm Manager / Notification Center and can fire after the UI process closes. Store the due date in Supabase; schedule/reschedule the local OS alarm on create, update, login and device sync.

For recurring monthly dates near month-end, calculate and schedule the next concrete due date after each payment rather than relying on day 29–31 recurrence in short months.

## 10. Real accounts and offline sync

The existing Supabase Auth session persists separately on every device. A user can sign in on Android, Windows or iOS and receives the same RLS-filtered rows and Realtime updates.

Security rules:

1. Ship only the Supabase anon/publishable key; it is designed for clients.
2. Never ship `service_role` in Android, iOS, Tauri or environment files bundled by Vite.
3. Keep RLS enabled and forced. Every table uses `auth.uid() = user_id`.
4. Use HTTPS/WSS only. Mixed Android content is disabled.
5. Treat the local cache as an app-sandboxed availability cache, not an authorization boundary.

Offline write flow implemented in `offlineStore.ts` and `AppContext.tsx`:

```text
UI write
  → create a client UUID + updated_at
  → update React state immediately
  → persist row in IndexedDB/Dexie
  → if offline: coalesce mutation into per-user outbox
  → Network plugin reports reconnect
  → refresh Supabase session
  → replay mutations oldest-first through normal RLS APIs
  → fetch/reconcile cloud snapshot
  → Realtime keeps memory and cache synchronized
```

IndexedDB is persistent and app-sandboxed in Capacitor WebViews and Tauri. For regulated data requiring encrypted-at-rest SQLite, replace the Dexie adapter with `@capacitor-community/sqlite` plus SQLCipher on mobile and a Tauri SQL plugin on desktop; keep the same repository/outbox interface. Store encryption keys in Android Keystore/iOS Keychain, never beside the database file.

For multi-device edit conflicts, the current practical policy is last accepted cloud write. For formal conflict guarantees, move writes to a Supabase RPC that accepts the client’s previous `updated_at` version and rejects stale updates, then show a merge dialog.

### Authentication

Cashbook uses Supabase email/password authentication only. It works directly in the native WebView and does not require OAuth provider credentials, browser plugins, custom callback schemes, or PKCE deep-link handling. Keep email confirmation and the production Site URL configured in the Supabase Authentication settings.

## 11. Release checklist

```bash
npm run typecheck
npm run lint
npm run build
npm run native:sync
```

Then verify on physical devices:

- New and returning Supabase login
- Entry creation while offline, app restart, reconnect and outbox flush
- Cross-device Realtime visibility
- UGX and foreign-currency historical conversion
- Device timezone and daylight-saving behavior
- Permission denied/granted flows
- Daily and due-date notifications after swiping the app away
- Notification cancellation after a debt is paid
- Android reboot and manufacturer battery-saving behavior
- Excel export/share sheet
- Dark mode, keyboard, safe areas and screen-reader labels

Before store submission, replace all generated icons/splash assets, add privacy policy/support URLs, complete Play Data Safety and Apple Privacy declarations, increment native build numbers, and test signed release builds—not only debug builds.
